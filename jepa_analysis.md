# JEPA Loss Plateau Analysis

## Что починили
1. TM→HV: теперь HV строится из TM-предсказания, не из raw SDR
2. LR вынесен в self.lr и поднят до 0.05
3. Нормализация raw[bit] по n_ctx в train_step error
4. Decay нормализован по n_ctx

## Результат
- Веса двигаются сильно: w0 -157 → -638 (было -5)
- Loss: 0.936 → 0.928 (было 0.930 → 0.930)
- Плато осталось, просто на новом уровне

## Коренная причина
`train_step` учит один вес w[bit] предсказывать:
- +1 когда actual_bit ≠ baseline_bit (10% битов)
- -1 когда actual_bit == baseline_bit (90% битов)

Это XOR — вес не может одновременно быть +1 и -1. Оптимум: w ≈ -4 (усреднение 9:1). Loss никогда не уйдёт ниже ~0.93.

## Что нужно
Выход из архитектурного тупика — два варианта:
1. **Predict difference HV**: вместо raw→residual, учить предсказывать actual HV напрямую (не residual)
2. **GTM/рекуррентность**: предсказывать SDR на TM, и сравнивать с actual SDR через overlap
