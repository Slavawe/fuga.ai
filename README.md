<h1 align="center">Fuga — Непрерывная Генерация Кода через Byte-VSA/JEPA</h1>

> **Статус: v9 (Byte-H-JEPA)** — единый файл FUGA1 (текст+код, чистые байты,
> без словарей). Релиз: **fuga_v7_1_final.fuga** (v7.1@1.2M) на Hugging Face
> [`Kateira1123/fuga-v7.1`](https://huggingface.co/Kateira1123/fuga-v7.1).
> В разработке: **v9 — трёхуровневая иерархия Macro→Patch→Byte (Byte-H-JEPA)**.

**Ядро AGI без трансформеров**: байтовый уровень (как MegaByte/ByT5) +
патчевый граф (two-speed) + латентные эмбеддинги (JEPA). Обучение — **честный
Widrow-Hoff / LMS-дельта** (`err = t − W·x`, обновление на каждой паре), без
backprop и батч-градиентов. Декодирование — косинусный выбор по латентам с
gate-коридорами и repetition-штрафами. Генерирует связный текст и C-код из
корпусов без токенизаторов и словарей.

---

## Архитектура (текущая)

### Единый формат FUGA1
Один файл, секции `[u32 tag][u32 len][bytes]`:

| tag | секция | размер |
|-----|--------|--------|
| 1 | LOCAL_W (байтовый Widrow-Hoff) | 512² |
| 2 | PATCH_W (патчевый граф) | 512² |
| 3 | OWM_P (защита направлений) | 512² |
| 4 | META (steps/ctx/version) | 24B |
| 7 | **MACRO_W (Byte-H-JEPA, v9)** | 512² |
| 6 | KAN_C (сплайны на остатке) | 512²×6 |

C++ (`cpp/fuga_core.h`) и Rust бинарно-совместимы (бит-в-бит roundtrip).

### Трёхуровневая иерархия (v9, Byte-H-JEPA)

```
Macro-Level (W_macro)  — семантический вектор намерения: предсказывает
                         латент будущего состояния/узла в эмбеддингах
        │  z_{t+1}
Patch-Level (W_patch)  — разворачивает в синтаксический каркас:
                         top-K коридор 2-байт патчей (for/if/структуры)
        │  коридор байтов
Byte-Level (W_local)   — точечная набивка символов по косинусной уверенности
                         (гибрид-перехват: локальный W достраивает имена)
```

- **Лосс Macro в пространстве эмбеддингов**: косинус/L2 между `\hat{z}` и
  `E(y)` — вариации отступов в байтах почти невидимы в латенте.
- **Локальный лосс** между уровнями (Forward-Forward): никакого глобального
  градиента, Widrow-Hoff на каждом уровне отдельно.

## Ключевые принципы (проверены честными A/B)

- **Окно декодирования = ctx+1**: обучение `data[i-ctxw..=i]`; ctx=8 →
  window=9. Несинхронные окна душат декодер (vity is — репетиционные циклы).
- **Словесный repetition penalty** (rep_word=0.20) бьёт word-аттракторы
  («the red»), байтовый штраф не справлялся (разрыв top-1/top-2 огромен).
- **Фразовый penalty** (rep_phrase=0.8, PHR_LEN=12) физически срезает
  фразовые циклы (99B → 38B) и переводит генерацию к соседним конструкциям.
- **Патчевый горизонт** `--patch-ctx` (рабочий 8 патчей = 16 байт; 32 байта
  был 4× медленнее и недоучивал Wp).
- **Syntax Loss** (v8): tree-sitter C-AST errors на чекпоинтах — метрика
  валидности дерева (`C-AST errors=0` = валидный C).
- **Детерминизм**: `cmp` бинарная идентичность чекпоинтов; сериализация
  MSE=0 на каждом прогоне (0/262144 несовпадающих).

## Декодеры (инференс, tm_generate.rs)

| Декодер | Механика | Роль |
|---------|----------|------|
| `tm_generate_cosine_gate_v2` | косинус + rep_word/rep_phrase | базовая линия |
| `tm_generate_megabyte_v2` | патч решает ДО байтов (top-K коридор), ws_pen | длина 200B на код-сидах |
| `tm_generate_megabyte_v3` | + макро-кондиционирование (βm·cos(W_macro·x_ctx)) | v9, семантика |
| **гибрид-перехват** (conf_th=0.05) | локальный W достраивает имя, если его косинус выше коридорного | точные имена API |

Итоговая конфигурация: `α=0, τ=0.01, corridor=0, β=0 (v2)/0.3 (MB2),
rep_word=0.20, rep_phrase=0.8, window=9, PHR_LEN=12`.

## Конвейер обучения (unified_gpu_train)

1. **CPU-поток**: читает JSONL-корпуса, строит окна (byte), патчевые окна
   (горизонт), макро-пары (латент окна → латент будущего окна/узла),
   кодирует SDR → латент (детерминированный проектор).
2. **GPU (wgpu)**: три канала в VRAM — W_local, W_patch, KAN-сплайны;
   Widrow-Hoff дельты пачками, один `sync()` на пачку (batch dispatch).
3. **λ-curriculum** (Patch Loss): `λ(t) = floor + (start−floor)·exp(−t/τ)`,
   τ=500K: жёсткая сшивка графа в ранней фазе → мягкая к концу.
4. **Чекпоинты** `--ckpt-every`: единый FUGA1 + метрики остатка + Syntax Loss.

Запуск: `unified_gpu_train --jsonl "a.jsonl,b.jsonl" --max-steps 1500000
--ctx 8 --patch-ctx 8 --lambda-patch 0.4 --lambda-tau 500000 --lr-macro 0.05
--out fuga_unified_v9.fuga`

Долгие прогоны — через `systemd-run` (переживают перезапуски шлюза):
`systemd-run --user --unit=fuga-v9 --working-directory=/home/slava/fuga ./run_v9_systemd.sh 1500000 /home/slava/fuga/fuga_unified_v9.fuga`

## Инструменты верификации

- `v6_validate <ckpt>` — A/B v2/MB2/β-проходы, все сиды (текст+код)
- `macro_validate <ckpt>` — A/B MB2 vs MB3 (макро-кондиционирование)
- `name_metric.py <ckpt>` — точность имён: топ snake_case-имён корпуса в декодах
- `macro_ab` — синтетический пруф разделимости латент-целей (16/16, 100%)
- `w_diag` / встроенные SERIAL-тесты — бинарная идентичность чекпоинтов

## Известные баги и уроки (важно для разработки)

1. **Глобальный LATENT_ENC_CACHE без лимита = OOM** на больших корпусах
   (пик 4.4G за 29s) → лимит 200K записей (clear при переполнении).
2. **tree-sitter в горячем пути опасен**: не-UTF8 строки зацикливают парсер
   (CPU 100%, пары стоят на 65536) → AST-разметка только вне обучения.
3. **Строки-монстры** (1MB в corpus.jsonl) = 1M пар ≈ 40 мин «зависания» →
   пропуск строк >64KB.
4. **Макро-канал стоит ~50% скорости** (750 → 430 pairs/s) — цена JEPA-уровня.
5. **Память машины 7.5GB**: перед полным прогоном освобождать RAM
   (Firefox/Telegram/Chromium), иначе системный OOM-kill.
6. **systemd-run — надёжный запуск** долгих прогонов: переживает перезапуски
   Hermes-шлюза (фоновые процессы Hermes убиваются при рестарте).
