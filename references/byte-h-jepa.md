# Byte-H-JEPA: Архитектурное сопряжение для Fuga

> Статус: **ПЛАН следующей сессии** (зафиксирован 11.08, решение пользователя).
> Фундамент: JEPA-ядро уже есть в стеке — `src/ai/latent_jepa.rs`
> (`SdrEncoder` 512-мер, `LatentPredictor::predict_next`, `predict_next_rnn`).

## Проблема, которую решаем

- **Размытие имён функций**: `codetoint` вместо `codepoint_to_utf8` —
  байтовый граф не удерживает строгое назначение API через длинный поток.
- **Пробельная разреженность**: генераторы падают в вариации отступов,
  пытаясь выучить миллионы вариантов форматирования.
- Нужен уровень, где **намерение** (семантика) отделено от **синтаксиса**.

## 1. Трёхуровневая иерархия абстракции

```
Macro-Level (H-JEPA Latent Predictor)   ← НОВЫЙ уровень
   предсказывает семантический вектор намерения z_{t+1}
   (непрерывный латент: «блок обработки Unicode-ошибок»,
   «цикл обхода массива»)
        │  z_{t+1} (LatentVector, 512-dim)
        ▼
Patch-Level (W_patch)                    ← СУЩЕСТВУЕТ
   разворачивает латент в синтаксический каркас:
   top-K коридор патчей (for/if, C-структуры, границы функций)
        │  коридор байтов
        ▼
Byte-Level (W_local)                     ← СУЩЕСТВУЕТ
   точечная набивка символов по косинусной уверенности
   (v2/MB2 гибрид-перехват, conf_th=0.05)
```

**Ключ**: Macro-уровень держит ЗНАЧЕНИЕ (какой API/конструкция),
Patch разворачивает синтаксис, Byte добивает символы. Имя функции
`codepoint_to_utf8` живёт в семантическом векторе — поток не размывает его.

## 2. Predicting in Embedding Space (устранение генеративного шума)

- Лосс считается **в пространстве эмбеддингов**: косинусное/L2 расстояние
  между предсказанным латентом `\hat{y}` и реальным `E(y)`.
- Вариации отступов/пробелов, которые в байтовом пространстве выглядят
  как огромные ошибки, в эмбеддинге почти невидимы (там латент
  семантически инвариантен).
- Совместимость с философией Fuga: никакого backprop через все слои —
  **локальный лосс** между W_patch и W_local (Forward-Forward / local loss).

## 3. AST-Masked Byte-JEPA (рекомендуемая версия)

Вместо случайной маскировки патчей (V-JEPA) — маска по AST:

1. **Кодер**: прошлый байтовый контекст X → вектор состояния z_t.
2. **Предиктор**: предсказывает эмбеддинг будущего AST-узла `\hat{z}_{t+1}`.
3. **W_patch**: декодирует `\hat{z}_{t+1}` в конкретный коридор патчей.

AST-узлы = tree-sitter C/Rust (уже зависимость проекта, используется
в `syntax_error_count`/`multi/language.rs`). Маскируем будущий узел —
модель учится предсказывать его латент, а не сырые байты.

## 5. Ожидаемый эффект

- `codetoint` → `codepoint_to_utf8`: семантический вектор удерживает
  назначение API независимо от длины байтового потока.
- Устранение пробельной разреженности: лосс в эмбеддингах игнорирует
  байтовый шум форматирования.
- Ветвление графа (v8.1@1M) сохраняется — Macro задаёт намерение,
  Patch/Byte продолжают как раньше.

## 6. Порядок реализации (следующая сессия)

1. **Математика + проверка в изоляции**: W_macro err =
   z_{t+1} − W_macro·z_t через Widrow-Hoff, на синтетике (2 простых
   семантических класса латентов) — честный пруф, что латент-цели
   линейно разделимы.
2. **Интеграция трейнера**: третий канал с `--lambda-macro`, горизонт
   макро-окна (константа, например 16 байт байтов → 8 макро-шагов).
3. **Декодер MB3**: z_{t+1} бьёт по W_patch (аддитивный β_macro),
   гибрид-перехват остаётся на Byte-уровне.
4. **A/B честный**: v7.1 (имена) vs v8.1-структура vs MB3 (обе цели)
   на name_metric.py + C-AST errors.
5. **AST-маска**: tree-sitter будущий узел → маска в обучении латента.

## 7. Риски и честные ограничения

- LatentPredictor уже умеет predict_next — но вход у него строковый
  (структурный), нужен байтовый путь. Проверить семантическую
  разделимость латентов синтетикой ДО интеграции.
- Третий канал = +33% CPU-подготовки (уже узкое место) — может
  потребоваться кэширование латентов.
- V-JEPA-подход калибруется m_cos/τ — параметры H-JEPA придётся
  калибровать с нуля.
