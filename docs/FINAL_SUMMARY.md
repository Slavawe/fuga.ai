## 💡 Уроки и инсайты

### 1. Почему standalone быстрее, чем ожидалось?

**Упрощённый энкодер** (`simple_encode`):
- Хэш-проекция без кэша: O(bytes × LATENT_DIM)
- Но: CPU cache-friendly (3MB весов в L3)
- Результат: 552-608 pairs/s на CPU

**Полный SdrEncoder** (в unified_gpu_train.rs):
- Structure-fold + хэш-проекция: O(164 bits × LATENT_DIM)
- Кэш на 200K окон → hit rate 98%
- Результат: 650-750 pairs/s на CPU, 800-900 на GPU

**Вывод:** Простота бьёт сложность на малых масштабах. Кэш важнее абсолютной скорости.

---

### 2. OWM vs регуляризация (L2, dropout)

**L2 регуляризация:**
```
ΔW = lr · (err ⊗ x − λ · W)
```
Штрафует ВСЕ веса одинаково → забывание uniform.

**OWM:**
```
ΔW = lr · err ⊗ (P_owm · x)
```
Штрафует только направления НЕ в null-space P → **селективная защита**.

**Эксперимент показал:** OWM аннулирует старые направления на 730×, L2 не может дать такой избирательности.

---

### 3. Два канала vs один широкий

**Альтернатива:** Один W размера 1024×1024 вместо двух 512×512.

**Проблема:** Один канал не разделяет масштабы:
- Байтовые переходы (`e→r`, `i→n`) — локальные, высокочастотные
- Патчевые переходы (`fn` → `std`, `}` → `pub mod`) — глобальные, низкочастотные

**Решение v10:** Два канала с разными горизонтами (9 байт vs 16 байт) → естественное разделение по частоте.

**Аналогия:** Wavelet decomposition — low-pass + high-pass фильтры дают лучшее сжатие, чем один широкополосный.
